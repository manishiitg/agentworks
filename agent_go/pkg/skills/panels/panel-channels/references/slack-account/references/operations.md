## Personal Slack accounts

Use `integrations` to list saved accounts, connect a new one, add it to this item, remove it only here, or disconnect it everywhere. On the website, open **Slack → Use Slack as me**, connect or reconnect your account, then choose **Use here**. The bot connection and personal sign-in status appear together; both use the same saved records as the chat tools. Existing Builders (including workflow editors) can explicitly add their own saved account; only the account owner signs in or reconnects, while owners or administrators can disconnect the saved connection. Signing in opens Slack in the browser, never a terminal or a request for a token in chat.

Connect once and explicitly add the account to every item that should use it. Shared runs use the account selected for this item, not the caller's Slack login. Messages appear as sent by that person with Slack's app attribution. Anyone who can run or change the item can send as that person through it. State this consequence when adding the account. Removing it here leaves other items connected. It stays selected until explicitly removed, including after its connector loses Builder access.

Discover the attached Slack connection with `mcp action=list`, inspect its live tools, then use `call_mcp_tool`. Resolve the actual recipient/channel before sending. For a new DM, Slack needs `im:write`; use the live conversation-creation tool rather than guessing a channel. Report a pending sign-in or Slack error accurately. Personal Slack and bot messaging use separate connections and identities. Use only tools actually available in this product; do not substitute a bot for the person's selected account, or the reverse.

Before saying a named Slack app is missing, inspect `sign_in_apps action=list`, `integrations action=slack_list_saved` and `integrations action=slack_bot_list_saved` using the tools available to this chat. If an inventory cannot be read, say which check is unavailable; do not claim that it contains no matching record. A saved bot may match the name even when no personal sign-in app is registered. Confirm that bot is saved, explain the separate personal approval, and reuse that existing internal Slack app where supported rather than requiring a new app or a fixed name.

An administrator sets up the sign-in app once in **Slack → Use Slack as me → Set up Slack sign-in**, or with `sign_in_apps` in chat/MCP. The app may have any name. Enable its Slack MCP Server feature in the Slack app's Agents settings, register the exact callback URL and required user scopes returned by the platform, then store its client ID and secret through the existing Vault tool in this Crew or Goal chat. Slack may require workspace app approval. See https://docs.slack.dev/ai/slack-mcp-server/.

Bot/app tokens cannot be used to infer or replace an OAuth client ID or secret. Ask only for missing setup fields. Never echo secret values. Do not enable PKCE, change callback handling or rotate bot credentials as a side effect of this setup. If Slack rejects a returned callback, report that exact blocker rather than inventing a working address or promising it was verified.
