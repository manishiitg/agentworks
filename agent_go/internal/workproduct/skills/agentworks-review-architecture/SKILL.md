# Review lens 2: architecture (is this the right approach, built simply)

This is the old Autopilot 'architecture review', now yours. Use it when results stay weak, the plan keeps growing without a matching gain, the person's intent changes, or on a monthly objective check. Size is a reason to look, not proof of a defect.

## Method
1. Start from the goal (soul file), current company facts and the person's recorded decisions. Then real outputs, comparable results, cost and earlier lessons. Read only as much plan, config or logs as it takes to settle the question. Missing measurements limit your conclusion; they do not forbid considering a clearly better approach.
2. Ask: **what would I build today if this plan did not exist?** Then compare: keep it, remove unproductive work, combine steps, change the approach, or retire it.
3. Use the design skills when needed: `plan-design`, `routing`, `schedules`, `step-config`, `step-description`, and `measurement-plan` guidance. For a model change, keep the person's explicit choices and compare real quality, cost and latency; run counts alone never justify a downgrade.

## Find the bottleneck (when the goal is measured but not moving)
1. Draw the chain from the work to the goal in a few links (for example: notes and comments, profile visits, subscribes; or: leads found, connected, replied, meeting). Use the Goal's own records (database, run outputs) for each link.
2. Count each link over the same window (this week vs last, last four weeks) and compute the rate between links. The weakest or the one that dropped is the bottleneck.
3. Compare the segments the Goal already has (groups, channels, audiences): which converts best, and is effort going where it converts?
4. Cost per outcome (below). 5. Conclude in one line: the bottleneck, the evidence, the one change most likely to move it. With a small sample say so and propose a test (strategy lens) instead of a conclusion.

## Costs
Use `costs` action `summary` for the aggregate available to this Crew. Step-level cost queries have no Crew tool yet; use authorized saved cost reports where available until the platform adds a tool, and say when a comparison cannot be verified. Useful questions: last 7 days vs the 7 before; which steps cost most; which models. Judge **cost per goal result** (per reply, per subscriber), not cost alone. A step that costs a lot and moves nothing is the candidate to cut or make cheaper (a smaller model, a script instead of an agent, fewer retries). Never change models or spending yourself; propose it with the numbers.

## Conclude
The useful outcome, the evidence, the uncertainty and a recommendation. A technical failure gets one hand-off to the Builder; keep judging what would limit the goal after it is fixed. A supported 'no change needed' is a good answer. Prefer removing or simplifying over adding another rule.

## What is whose
The Builder implements within existing permissions. Removing a redundant implementation rule is ordinary simplification. Replacing the plan, deleting steps or schedules, a new goal, or retiring the Goal is the person's decision: prepare it once, with the proposed scope and how to undo it, and never do it automatically.
