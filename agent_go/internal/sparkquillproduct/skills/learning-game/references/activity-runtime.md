# SparkQuill activity runtime

Save the game at `activities/<yyyy-mm-dd>-<slug>/game.sq.html` and list it in `create_learning_activity.items`. The tool finishes it into `game.html`, preserving inline JavaScript, SVG, Canvas and the page's own CSS. It supplies the SQ bridge before body scripts. There is no imposed game layout or engine. If a library is useful, bundle its needed runtime inline instead of depending on a CDN.

Put scripts in the body; scripts in the source head are removed. The finisher removes iframes, links and external stylesheets, unwraps forms and details, and strips remote resource references. Use buttons for local controls. It assigns ids to sections, figures and `.q` questions; use other elements for custom game ids or select stable data attributes. Inspect the finalization report and test `game.html`, since source-only testing misses these transformations.

The viewer runs the page in a sandboxed `srcDoc` iframe. Do not rely on localStorage, cookies, cross-page navigation or a development server. Keep CSS and scripts inline. Save images, audio and other media beside the page and reference them with relative `src` attributes; the viewer rewrites these and video `poster` attributes to authenticated asset URLs. It does not rewrite CSS `url(...)`, JavaScript fetch paths or dynamically constructed asset URLs. For Canvas sprites, load a declared `<img src="sprite.png">` and draw that element after it loads. Inline SVG, procedural drawing and embedded assets are also options. Use Google Images through `agent_browser` when sourcing internet images: visit the source, save and inspect the actual asset, and retain required credit.

Keep active play in memory. Save compact JSON checkpoints with `SQ.saveGame('progress', data)`; restore with `SQ.loadGame('progress', function(saved) { ... })`. Keys are scoped to the activity, saved state is limited to 65,536 serialized characters, and parent preview returns null and does not save. Validate saved data and support a fresh start. Save on meaningful changes, not every animation frame. Do not wait indefinitely for a load callback before allowing play.

`SQ.choose(text, button)` and `SQ.answer(qid, value, button)` submit a tutor turn and disable the supplied button. Use ordinary JavaScript for movement and locally checked actions; calling the tutor for each tap makes play wait for a model response. Reserve `.q` for tutor-tracked questions, since the finisher adds an answer space. Formal tests retain their requested feedback and timing rules; their answer keys stay outside the child's folder. Local feedback for a learning game can explain what happened and help the child retry.
