Agent execution and access

The backend resolves the authenticated account, project and agent profile before admitting tools. The interface displays those decisions.

Authenticated request → project and profile access → admitted runtime
  Native CLI tools → configured CLI confinement and folder grants
  Platform tools → session-bound bridge → workspace and product access checks
  Browser tools → admitted browser capability and selected browser session

Separate enforced boundaries

A native CLI's built-in tools and platform workspace tools are separate execution paths. A restriction reported by one does not describe the permissions of the other. Both must enforce their actual grants; agents should report a real refusal from the attempted path.

Files and secrets

Workspace references, project roles, folder grants and protected paths determine file access. Secret values reach authorized work through its environment and must not be printed, stored in source, or sent in messages.

Browsers

Browser capability and the selected session determine which browser a tool can control. A direct CDP browser is a host process whose file access is independent of a workspace shell sandbox. The browser extension rejects file URLs. See the browser guide for supported modes.

Shared contracts

Products reuse the profile registry, session transcript, tool bridge, workspace grants and channel transports. Domain records and presentation remain product-owned. See the product manifest guide.
